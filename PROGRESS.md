## 0. Read this first (instructions for Claude / any agent)

**Goal.** Build and honestly evaluate the model the team proposed, **MW-AeroFusion-Net** (wavelet + adaptive
diffusion graph + ConvLSTM + Transformer + source-group gating), for PM2.5 forecasting at +1/+24/+48 h over
Indian cities. Serve it in the existing live platform. Publish one IEEE-conference paper (INDICON / CONECCT /
ICCCNT or a Springer applied-AI conference). **Never** a pay-to-publish venue (IJRASET, IJERT, IJIRT…);
check UGC-CARE / Scopus listing first.

**Hard rules. Never break these.**
1. **No hand-typed results.** Every number in the paper, report, README, Model Lab UI or this file must come from a
   run artifact `ml/runs/<run_id>/metrics.json`. Tables are generated by `ml/scripts/make_tables.py`.
   If a number has no run_id, it does not exist. `backend/app/data/metrics_illustrative.json` must be deleted (P0.3)
   and must never come back (CI check in P2).
2. **Test set is frozen.** Test = 2023-01-01 → 2024-12-31 (UTC), plus the PM-only check 2025-04-01 → 2025-09-30 (revised 2026-10-15, §9). Never tune, select, early-stop or "peek" on it.
   Its content hash lives in `ml/data/SPLITS.lock`. Only `ml/scripts/final_eval.py` may read it, and only in P4.
3. **No future leakage.** Inputs at issue time `t0` may only contain data that would have been *available* at
   `t0` (respect data latency, see §3.4). Wavelets are computed causally inside each input window. Normalisation
   statistics come from the training years only. Never interpolate *targets*.
4. **No "causal" wording.** The proposal's "causal attention" is implemented as *source-group attribution gating*.
   Call its output "learned attribution", never "causal contribution" or "% source apportionment", unless P4's
   validation passes, and even then say "attribution".
5. **No novelty claim** ("first", "novel", "nobody has…") unless the related-work matrix (P0.6) supports it.
6. **Never silently drop a proposed component.** All five components are built (P3). If one doesn't help, that is
   reported as an ablation result. It is never deleted from the story.
7. **Secrets** live only in `backend/.env`, `ml/.env` (both gitignored) and `~/.cdsapirc`. Never print them,
   never commit them, never paste them into chat. The deployed backend gets only the keys it needs.
8. **All timestamps are UTC internally.** Convert CPCB/XKDR (IST, UTC+5:30) at ingest (§3.3).
9. When something in this plan is marked **VERIFY**, check it against the real API/data before building on it,
   and record the answer in §9 (Decision log).

**How to work a task.** Pick the first unchecked task of the current phase. Read its *Acceptance* line. Implement it.
Run its tests. Tick the box, add a one-line note with date and run_id/file. Phases may overlap only where stated.

## 2. Proposal → implementation traceability (show this to the guide in P0.1)

| Proposal item | Implemented as | Deviation & reason |
|---|---|---|
| Multi-resolution wavelet decomposition | `models/wavelet.py`: causal stationary wavelet (SWT/à-trous, `db4`, 3 levels) computed **inside each 72 h input window** | Full-series DWT leaks future samples; causal variant is the honest equivalent |
| Adaptive diffusion graph learning (Haversine + wind) | `models/graph.py`: diffusion conv with (a) static wind-aware adjacency (distance + upwind alignment) and (b) learned adaptive adjacency (node embeddings) | none; both variants ablated |
| ConvLSTM on grid maps (B,T,C,H,W) | `models/convlstm.py`: ConvLSTM over **gridded exogenous fields** (CAMS AOD/dust/PM2.5 analyses, wind u/v, BLH, rasterised FIRMS FRP) on a 0.75° India grid, sampled at node locations → per-node regional-context embedding | PM2.5 targets are station points, not a grid; ConvLSTM is used where gridded data exists |
| Transformer encoder | `models/temporal.py`: Transformer encoder over time per node | none; ablated vs GRU |
| Causal attention (% source contributions) | `models/gating.py`: source-group attribution gating (variable-selection softmax over groups: fire, meteorology, dust, traffic-proxy, CAMS, history) + L1 sparsity | Not causal identification → renamed; validated in P4.4. "Traffic" = proxy (NO₂, CO, weekday/holiday), since no traffic data exists |
| Inputs: CPCB, IMD weather, MODIS/VIIRS fires, events | CPCB via XKDR (hourly), ERA5 (in place of IMD; open, hourly, gridded), VIIRS + MODIS fires, CAMS, calendar/events | IMD archive not openly hourly; ERA5 is the standard substitute |
| Outputs: t+1/24/48, AQI class, hotspots, attribution maps | PM2.5 at +1/+24/+48; AQI class & hotspots **derived** from forecast via CPCB breakpoints; gating weights per node | One model claim instead of three heads |
| Baselines: LSTM, CNN-LSTM, ConvLSTM | Kept, **plus** persistence, climatology, CAMS raw, CAMS+bias-correction, LightGBM, PM2.5-GNN, Graph WaveNet | Reviewers reject papers that only beat LSTMs |
| Metrics RMSE/MAE/R² + ablations | Plus bias, skill vs persistence and vs CAMS, CSI for PM2.5 > 250, AQI-class F1, 3–5 seeds, Diebold-Mariano test | Required for acceptance |
| Real-time deployment (was *out of scope*) | Already built (Phase 0); trained model served via ONNX in P5 | Scope grew |

### 3.2 Spatial design (decided)
- **Target nodes = CPCB stations** inside the 33 platform cities (`backend/app/data/cities.json`). Each station is
  kept if it has data starting **≤ 2020-01-01** and **≥ 60 % hourly completeness** from its start to 2024-12-31 (end of the test split).
  Expected ≈ 80–200 stations; record the exact list in `ml/data/stations_v1.csv` and freeze it.
  *Reason:* city medians drift as CPCB adds stations (Delhi went from a few stations to ~40), and a fixed station
  panel removes that drift.
- **City-level numbers** (for the paper's city tables and the platform) = mean of that city's station *predictions*
  and *observations*, computed at evaluation time only.
- **Context nodes = 17 upwind source regions** (`source_regions` in `cities.json`). They carry met/fire/CAMS
  features only; they have no target and their loss is masked. They let the graph carry Punjab/Haryana smoke towards Delhi.
- **Graph edges:** k-nearest (k=8) within 600 km. Static weight = exp(−d/σ) × max(0, cos(wind dir − bearing)),
  following PM2.5-GNN. Adaptive adjacency is learned on top. Expect the graph to matter mostly in the Indo-Gangetic
  Plain, so report IGP vs rest separately.
- **Grid (ConvLSTM):** India bbox 5–38 °N, 66–98 °E at 0.75° → 44 × 43 cells, 3-hourly. Fallback 1.5° (22 × 22).

### 3.3 Time design (decided)
- Internal clock **UTC**, hourly. Build XKDR hourly values **from `agg=raw` (15-min) re-binned to UTC hours**, which
  avoids the IST :30 offset. **VERIFY** in P1.2 whether raw timestamps mark the interval start or end, and record it.
- Issue times `t0` every hour for training samples; evaluation uses issue times **00 UTC and 12 UTC** (matching CAMS runs).
- Input window: past **72 h**. Leads: **+1, +24, +48 h** (the model predicts all 48 steps; the paper reports these 3).
- Splits (UTC):

  - **extra test (PM-only)** 2025-04-01 → 2025-09-30: ~320 stations with PM2.5/PM10 only; frozen like test; robustness check
    (pre-monsoon + monsoon) with NO₂/CO/O₃ inputs masked

| Input | Usable at t0 if timestamp ≤ |

### 3.5 Three input settings (report all three; label clearly)
- **S-A operational, past-only.** Past 72 h of obs, met, fires and CAMS analyses. **This is the primary setting.**
- **S-B operational + CAMS forecast.** S-A plus the latest available CAMS forecast for leads 1–48 at each node. This frames the model as CAMS post-processing.
  It is the setting most likely to beat CAMS. Also report S-B without CAMS (= S-A) to show the value of the model itself.
- **S-C perfect-prognosis (upper bound only).** S-A plus *future* ERA5 met at true values. **Never** present it as a forecast.

### 3.6 Features per node per hour (`ml/configs/features_v1.yaml`, frozen at feature freeze)
- **history:** pm25, pm10, no2, co, o3, missing-mask per pollutant
- **met:** t2m, rh, u10, v10, wind speed, pressure, precip, blh, ventilation (= wind × blh)
- **fire:** fires_300km, frp_300km, fires_upwind_500km (upwind = within ±45° of the wind direction, measured from the city towards the source)
- **dust/CAMS:** cams_pm25, cams_aod550, cams_dust_aod (analysis, lead 0)
- **traffic-proxy:** no2, co (from history), weekday, holiday
- **calendar:** hour sin/cos (UTC+5.5 local time), day-of-year sin/cos, diwali_window, stubble_season, lockdown
- **static:** lat, lon, elevation, coastal, region, city population

### 3.7 QC rules (`ml/aerofusion_ml/data/qc.py`, unit-tested)
- Physical bounds: PM2.5 ∈ [0, 1500] µg/m³, PM10 ∈ [0, 2000]. Drop 999 and other sentinel values and negatives.
- **Flatline:** the same value for ≥ 6 consecutive hours → set NaN.
- **Spike:** rolling 24 h median ± 6 × MAD → NaN, unless ≥ 2 stations in the same city spike together, which is a real event.
- **PM2.5 > PM10 × 1.05:** flag. Keep, but count it in the data card.
- **Inputs:** last value carried forward for ≤ 3 h (causal; *was* linear interpolation, changed 2026-10-15, §9), the rest NaN + mask. **Targets:** never filled; masked in the loss.
- Data card `ml/data/DATA_CARD.md` (generated): per-station coverage, % removed by each rule, final counts.

### 3.8 Storage & formats
- Raw downloads → `ml/data/raw/<source>/…`, gitignored, with `ml/data/raw/MANIFEST.json` (url, date, sha256, bytes).
- Processed → `ml/data/processed/dataset_v1.zarr` (xarray). Expected sizes:
  - XKDR raw parquet ≈ 2–5 GB
  - CAMS forecast India subset ≈ 5–20 GB
  - ERA5 grid ≈ 5–15 GB
  - FIRMS ≈ 1 GB
  - processed < 3 GB
  - **Total disk: plan 100–150 GB free.**

### 3.9 Dataset contract (`dataset_v1.zarr`)
```
node dataset   dims: time (UTC hourly, 2018-01-01..2025-09-30), node (stations + 17 regions)
  x_node[time,node,feat]  float32   (feature order = features_v1.yaml)
  m_node[time,node,feat]  uint8     1 = observed
  y[time,node]            float32   PM2.5 target, NaN where missing / context node
  node_meta: id, kind(station|region), city_slug, lat, lon, ...
grid dataset   dims: time (UTC 3-hourly), channel, lat(44), lon(43)
cams_fc        dims: run (00/12 UTC), lead (0..48 h), node, var
attrs: version="v1", created, git_sha, manifest_sha256, splits
```
The batch contract every model consumes (in `ml/aerofusion_ml/data/loader.py`):
```
batch = {x_node[B,72,N,F], m_node[B,72,N,F], x_grid[B,24,C,44,43], x_fc[B,48,N,Ffc] (S-B only),
         static[N,S], adj_static[N,N], y[B,48,N], y_mask[B,48,N], t0[B]}
model.forward(batch) -> {"pred": [B,48,N], "gates": [B,N,G] | None}
```
Every model (baselines included) implements this interface, so the ladder and the ablations are config switches.

## 7. Compute: does training need a better machine?

**Short answer: yes, ask the college. You need a GPU you can use for long, uninterrupted runs, not a more powerful one.**
The model is small. The cost is the number of runs (ladder + baselines + ablations × seeds × settings) and
the ConvLSTM branch.

**Estimates from the council, reconciled:**
- Model ≈ 1–3 M parameters.
- Peak VRAM ≈ 6–12 GB at batch 32 with the 0.75° ConvLSTM branch; < 4 GB without it.
- One run ≈ 1–4 GPU-hours on a T4-class GPU, ≈ 0.3–1 h on an RTX 4090.
- Total experiments ≈ 80–150 runs → **≈ 150–300 T4-GPU-hours (≈ 50–100 h on a 4090)**, concentrated in weeks 8–14.
- Data prep and LightGBM are CPU/RAM-bound (32–64 GB RAM helps); disk 100–150 GB.
